# Milestone 2 - Schemas, Validation, Guardrails, and Preview Contracts

## Goal
Implement the public Input Processor contracts and cheap pre-processing guardrails before OCR/PDF parsing is added.

## Scope Rules
* Preserve the existing `NormalizedInput`, `ImageContent`, and `PDFContent` contract.
* Do not add tables, bounding boxes, page objects, layout objects, coordinates, provenance, or OCR confidence to `NormalizedInput`.
* Validate attachments before expensive processing.
* Return structured safe errors instead of raw exceptions.

## Tasks

### Task 1 - Define internal request schemas
* Add `Attachment` with `filename`, `media_type`, and transient `content: bytes`.
* Add `InputRequest` with optional `user_query` and `attachments`.
* Validate missing/empty content and malformed attachment objects.
* Keep request schemas independent from API upload classes and file paths.

### Task 2 - Define processing result schemas
* Add `InputProcessingResult` with overall `success`, optional `normalized_input`, attachment-level errors, and warnings if needed.
* Add attachment-scoped status/error objects.
* Support full success, partial success, and complete failure.
* Ensure errors are safe for user display.

### Task 3 - Define error taxonomy
* Include at least:
  * `INVALID_INPUT`
  * `UNSUPPORTED_FORMAT`
  * `SIGNATURE_MISMATCH`
  * `FILE_TOO_LARGE`
  * `PDF_PAGE_LIMIT_EXCEEDED`
  * `OCR_FAILURE`
  * `EXTRACTION_FAILURE`
  * `UNREADABLE_CONTENT`
  * `PII_PROCESSING_FAILURE`
  * `SAFETY_REJECTION`
  * `INTERNAL_PROCESSING_ERROR`
* Do not leak stack traces, paths, credentials, or document text in error payloads.

### Task 4 - Define validated modality model
* Represent supported modalities as text, PNG, JPEG/JPG, and PDF.
* Use declared `media_type` plus actual signature inspection.
* Reject MIME/signature mismatch safely.
* Do not trust filenames or extensions alone.

### Task 5 - Implement input presence validation
* Accept text-only input.
* Accept attachments without text.
* Reject completely empty requests.
* Do not invent a user question when no text is provided.

### Task 6 - Implement supported media-type validation
* Accept only:
  * `image/png`
  * `image/jpeg`
  * `application/pdf`
* Treat `.jpg` and `.jpeg` as JPEG where content signature matches.
* Reject unsupported types before OCR/PDF processing.

### Task 7 - Implement file signature validation
* Verify PNG signature.
* Verify JPEG signature.
* Verify PDF signature/structure enough to reject obvious mismatches.
* Add tests for declared PDF with image bytes and declared image with non-image bytes.

### Task 8 - Implement file-size validation
* Enforce current confirmed upload requirement: file size `< 10 MB`.
* Make the limit configurable in one place.
* Test below limit, at boundary, and above limit.
* Do not pass oversized files to image/PDF processors.

### Task 9 - Implement PDF page-count validation shell
* Add a validation function for PDF page count before PDF processing.
* Keep the limit configurable.
* Mark the unresolved 5-vs-10 page decision in code comments/tests where needed.
* Use the final confirmed value once the team resolves it.

### Task 10 - Implement deterministic preview helpers
* Image preview: first 500 characters of extracted image text.
* PDF preview: 200 characters per page or equivalent page-aware behavior.
* Previews must not call an LLM.
* Keep preview logic separate from OCR/PDF extraction.

### Task 11 - Implement initial PII guardrail boundary
* Create an interface for PII detection/masking.
* Default behavior should be mask-and-continue once PII is detected.
* Do not silently treat PII detector failure as "no PII."
* Keep exact PII taxonomy/provider unresolved if not yet decided.

### Task 12 - Implement prompt-injection boundary
* Treat extracted document instructions as untrusted document content.
* Do not allow document text to alter system/developer instructions, routing, credentials, or policy.
* Do not use naive keyword-only rejection.
* Preserve ordinary government instructions as content.

### Task 13 - Add schema and validation tests
* Test `InputRequest`, `Attachment`, `InputProcessingResult`, and error taxonomy.
* Test empty request, text-only request, attachment-only request, and malformed attachments.
* Test unsupported format rejection.
* Test MIME/signature mismatch.
* Test size and PDF page-limit boundaries.

### Task 14 - Add synthetic validation fixtures
* Add tiny valid PNG and JPEG files with fictional text if practical.
* Add invalid bytes named as `.pdf`, `.png`, and `.jpg`.
* Add a small valid PDF for page-count validation.
* Add over-limit fixture via generated bytes in test code rather than committing a huge file.

## Exit Criteria
* Contracts exist and validate expected inputs.
* Unsupported, malformed, mismatched, oversized, and over-page-limit inputs are rejected before expensive processing.
* Preview helper behavior is deterministic.
* Guardrail tests cover validation, PII boundary, prompt-injection boundary, and safe error shape.
