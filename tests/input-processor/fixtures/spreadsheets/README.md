# Spreadsheet Fixtures

Spreadsheet fixtures must be synthetic, deterministic, and safe to commit.

Do not use real citizen records, real credentials, private workbooks, production exports, or genuine PII. Use fictional names, fictional identifiers, fictional addresses, and obviously synthetic government-style rows.

## Fixture Strategy

Prefer generating `.xlsx` workbooks in test code with helper functions instead of committing many binary files. Commit a workbook fixture only when binary compatibility with a real parser must be proven and the fixture is small, stable, and documented here.

Validation-only tests may use minimal Office Open XML ZIP package bytes. Parser and extraction tests should use real `.xlsx` workbooks generated by `openpyxl` after the parser implementation is wired.

Oversized files and very large cells should be generated in tests rather than committed.

## Safety Requirements

Spreadsheet fixtures must not include:

- raw private workbook exports
- real Aadhaar, PAN, passport, voter ID, phone, email, account, or address values
- real application records or status exports
- passwords, API keys, credentials, or tokens
- macros, VBA, or executable content
- hidden content copied from real files

Fixture names and test assertions may include safe counts, sheet names, cell coordinates, and synthetic workbook names. They must not include raw sensitive cell values in failure messages.

## Helper Guidance

Use `tests/input-processor/spreadsheet_fixture_helpers.py` for reusable workbook-byte builders.

Current helper support:

- minimal valid OOXML package bytes for validation/provider-boundary tests
- malformed OOXML package bytes
- corrupt ZIP-like bytes

Future helper support after parser implementation:

- `openpyxl` workbook generation for visible sheets
- hidden sheet, hidden row, and hidden column setup
- formulas, merged ranges, and Excel Tables
- long-cell and fictional-PII scenarios
